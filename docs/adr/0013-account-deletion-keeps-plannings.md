# Le compte peut être supprimé sans supprimer les plannings

La suppression de compte (`/api/delete-account`) retire le lien `userId`/`claimedAt` des participations, pose `hasQuit=true` (l'utilisateur « quitte » tous les plannings), supprime ses prefs (`planning_participants`) et le record `users` — mais **ne supprime jamais** les `planning_masters`, occurrences ni events. Les plannings ont une vie propre : plusieurs admins peuvent exister, l'adminToken seul suffit à administrer (même sans compte auth), et un admin sortant peut transmettre son lien admin pour transfert de responsabilité. L'alternative « tout supprimer en cascade » était plus propre techniquement mais détruirait les données d'autres participants ; l'alternative « bloquer la suppression tant qu'il reste des plannings admin » empêcherait de partir proprement. Trade-off assumé : le pseudonyme (`participants[].name`) reste visible dans les messages/réponses après suppression — pas d'anonymisation.
